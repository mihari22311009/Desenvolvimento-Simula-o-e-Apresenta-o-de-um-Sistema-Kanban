Sistema para Gestão de Reservas de uma Pousada

Projeto desenvolvido na disciplina de Metodologias Ágeis, com o objetivo de aplicar, na prática, os conceitos e princípios do Kanban na organização, acompanhamento e melhoria do fluxo de trabalho de uma equipe de desenvolvimento.

O projeto consiste na simulação do desenvolvimento de um sistema web para gerenciamento de reservas de uma pousada, utilizando um quadro Kanban para representar o fluxo de trabalho desde o recebimento de uma demanda até sua conclusão.

Sobre o Projeto

O sistema simula uma aplicação web responsável pelo gerenciamento das principais atividades relacionadas às reservas de uma pousada.

Entre as funcionalidades e demandas consideradas no projeto estão:

Gerenciamento de quartos e disponibilidade

Cadastro e gerenciamento de reservas

Gerenciamento de hóspedes

Registro de check-in

Registro de check-out

Cancelamento de reservas

Controle da ocupação dos quartos

Para organizar o desenvolvimento dessas funcionalidades, foi utilizado o Kanban, permitindo visualizar o andamento das tarefas e identificar possíveis problemas no fluxo de trabalho.

Objetivos

O principal objetivo do projeto foi compreender e aplicar o método Kanban por meio de uma simulação prática, observando como a organização visual das atividades pode contribuir para um fluxo de trabalho mais eficiente.

Durante o desenvolvimento, foram trabalhados conceitos como:

Visualização do fluxo de trabalho

Limitação do WIP (Work in Progress)

Priorização de tarefas

Identificação de gargalos

Controle de tarefas bloqueadas

Redução de tempo de espera

Melhoria contínua

Colaboração entre os integrantes da equipe

Fluxo Kanban

O quadro foi organizado em diferentes etapas, representando o caminho percorrido por cada tarefa até sua conclusão.

Solicitado

Nesta etapa ficam as demandas recebidas pela equipe, que ainda não foram analisadas ou preparadas para desenvolvimento.

Pronto para Desenvolver

As demandas que foram analisadas, detalhadas e priorizadas são movidas para essa etapa.

O objetivo é manter tarefas preparadas para que a equipe possa iniciar o desenvolvimento sem depender de novas informações.

Em Desenvolvimento

Nesta etapa ocorre a implementação das funcionalidades.

Os integrantes da equipe selecionam as tarefas disponíveis e iniciam seu desenvolvimento, respeitando os limites de WIP estabelecidos.

Revisão

Após o desenvolvimento, a tarefa passa por uma revisão realizada por outro integrante da equipe.

Essa etapa tem como objetivo verificar a implementação, identificar possíveis problemas e garantir que o trabalho esteja de acordo com os requisitos definidos.

Testes

Depois da revisão, a funcionalidade é encaminhada para testes e validação.

Nesta etapa é verificado se a funcionalidade está funcionando corretamente e se atende ao que foi solicitado.

Entregue

Quando a tarefa passa pelas etapas anteriores e é validada, ela é movida para Entregue.

Isso significa que a atividade foi concluída e está pronta para ser considerada como uma entrega finalizada.

Bloqueado

Foi utilizada a etiqueta Bloqueado para identificar tarefas que não conseguem avançar devido a algum impedimento.

Entre os possíveis motivos estão:

Dependência de outra tarefa;

Problemas técnicos;

Falta de informações;

Indisponibilidade de ambiente;

Outros impedimentos que impossibilitem o avanço da atividade.

Essa identificação permite que a equipe perceba rapidamente quais tarefas precisam de atenção.

Limites de WIP

Durante a simulação foram definidos limites de WIP (Work in Progress).

O WIP representa a quantidade de tarefas que podem estar sendo executadas simultaneamente em determinada etapa do fluxo.

A utilização desses limites teve como objetivo:

Evitar o excesso de tarefas simultâneas;

Aumentar o foco da equipe;

Evitar o acúmulo de atividades;

Incentivar a conclusão das tarefas antes de iniciar novas;

Facilitar a identificação de gargalos.

Dessa forma, quando uma etapa atingia seu limite de WIP, a equipe deveria priorizar a conclusão das tarefas existentes em vez de simplesmente iniciar novas atividades.

Simulação

Para avaliar o funcionamento do Kanban, foram realizadas três rodadas de simulação.

Durante cada rodada, as tarefas foram movimentadas entre as etapas de acordo com o seu estado atual.

A equipe observou:

Quantidade de tarefas em cada etapa;

Acúmulo de atividades;

Tarefas bloqueadas;

Tempo de espera;

Capacidade de cada etapa;

Impacto dos limites de WIP;

Fluxo das tarefas até a entrega.

A simulação permitiu observar que a velocidade de desenvolvimento não é o único fator que influencia o tempo de entrega.

Uma etapa com menor capacidade pode fazer com que as tarefas se acumulem e permaneçam esperando, afetando todo o fluxo.

Gargalo Identificado

Durante as três rodadas de simulação, foi identificado um gargalo recorrente na etapa de Testes.

As tarefas chegavam à etapa de testes em uma velocidade maior do que a capacidade disponível para realizar as validações.

Como consequência, algumas tarefas precisavam aguardar na fila antes de serem testadas.

Esse acúmulo aumentava o tempo de espera das atividades e dificultava a conclusão de novas tarefas.

A visualização proporcionada pelo Kanban facilitou a identificação desse problema, pois o acúmulo de cartões na etapa de Testes tornou o gargalo visualmente evidente.

Melhoria Realizada

Após a identificação do gargalo, foi realizada uma melhoria na organização visual da etapa de Testes.

Os itens foram separados em duas situações:

Testes em andamento — tarefas que estavam sendo efetivamente testadas;

Aguardando testes — tarefas prontas para validação, mas que ainda aguardavam disponibilidade para serem testadas.

Essa alteração permitiu diferenciar claramente o trabalho que estava sendo executado daquele que estava aguardando atendimento.

A mudança tornou o problema mais visível e facilitou o acompanhamento da fila de testes.

Essa ação também demonstra o princípio de melhoria contínua do Kanban, no qual a equipe observa o fluxo, identifica problemas e realiza ajustes para melhorar o processo.

Resultados

A simulação permitiu observar, na prática, diferentes efeitos da utilização do Kanban.

Limites de WIP

Foi possível perceber que limitar a quantidade de tarefas simultâneas ajuda a evitar o excesso de trabalho iniciado e incentiva a equipe a finalizar atividades antes de começar novas.

Identificação de Gargalos

O acúmulo de tarefas em Testes mostrou como uma etapa com capacidade limitada pode gerar filas e aumentar o tempo necessário para concluir uma atividade.

Visualização do Fluxo

O quadro permitiu acompanhar facilmente o estado de cada tarefa e identificar onde o trabalho estava se acumulando.

Priorização

A organização das demandas ajudou a equipe a definir quais atividades deveriam ser tratadas primeiro, principalmente em situações envolvendo urgência ou prazos definidos.

Tempo de Entrega

Foi possível observar que o tempo de conclusão de uma tarefa não depende somente do tempo de desenvolvimento.

Esperas, bloqueios, revisões e testes também influenciam diretamente o tempo total de entrega.

Melhoria Contínua

A identificação do gargalo e a reorganização da etapa de testes demonstraram a importância de analisar constantemente o fluxo e realizar melhorias quando problemas são identificados.

Conclusão

A utilização do Kanban possibilitou aplicar de forma prática os conceitos estudados na disciplina de Metodologias Ágeis.

Por meio da simulação do sistema de reservas da pousada, foi possível acompanhar o fluxo de uma demanda desde sua solicitação até a entrega, observando como fatores como WIP, priorização, bloqueios e gargalos podem interferir no processo de desenvolvimento.

O principal problema identificado foi o acúmulo de atividades na etapa de Testes. A partir dessa observação, a equipe realizou uma melhoria na organização visual dessa etapa, diferenciando as tarefas em execução daquelas que estavam aguardando atendimento.

Com isso, o projeto demonstrou que o Kanban não consiste apenas em organizar tarefas em colunas, mas também em:

Visualizar o trabalho, controlar o fluxo, identificar problemas e promover melhorias contínuas no processo.
